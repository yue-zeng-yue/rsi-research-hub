## Interpretation for the research agenda

**The improvement target needs to be explicit.** A changed harness, stronger task solver, and stronger improver require different tests. These four studies provide mechanisms and bounded outcomes, but they do not remove the need for same-start, same-budget improver comparisons. See their linked reviews for methods, numerical conditions, and source locators.

**Co-evolution now has a particularly relevant testbed.** CoEvoBench is a close evaluation reference for the repository's [compatibility-aware pair-selection proposal](../../research/model-harness-compatibility.md). A useful contribution must predict which intervention is worth making, rather than merely show that model and harness effects interact. Its public release requires an environment and provenance audit before it becomes an experiment dependency. This update does not claim that such an audit has passed.

**Weight-level work requires two different controls.** For direct edits, hold the edit primitives and candidate budget fixed while varying who proposes the change. For distillation, hold the training recipe and supervision access fixed while varying references and demonstrations. Combining these into a single ranking would obscure the resource and feedback differences.

**Evaluation feedback remains part of the method.** A protected test set, a reused selection set, and unlabeled target-input adaptation have different evidential roles. The reviews preserve those distinctions. Future reports should identify every flow of task text, labels, scores, and trajectories before interpreting a score as generalization.

**A code link is an artifact lead, not a reproduction result.** AutoMaster's inspected release contains skills and inference recipes. CoEvoBench has substantive source code but explicitly incomplete runtime acceptance and historical-equivalence limits. No author-linked code was verified for SelfWrite or TT-RSI. These are actionable reproduction constraints, not evidence that the papers' reported outcomes are false.

## Implications for the existing roadmap

Phase 2 remains **planned**. No benchmark run, model training, or independent scientific reproduction was performed in this update.

1. Keep the direct paired update/no-update comparison as the next milestone; choose one environment and fixed executor before spending compute.
2. Treat CoEvoBench as a candidate protocol and close baseline. Resolve evaluator isolation, artifact provenance, and final-evaluation readiness before using its implementation.
3. Preserve a sealed task-family audit and a matched-budget sampling control. Record reference inputs, rejected candidates, proposer and teacher calls, training, and integration costs.
4. For a later model-level study, compare direct edits and distillation only under explicitly matched feedback and resource conditions. Evaluate regressions outside the development domain.

These are adjustments to baseline selection and evidence requirements, not a claim of a new algorithm or a completed experimental phase.
